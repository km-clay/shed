*functions* *bundled-functions* *shed-functions*

#SHED FUNCTIONS#

Shed ships with a set of shell functions written in shed's own
scripting language. They complement the builtins (|builtin-commands|)
and serve as library-style implementations of common operations.

Bundled functions are autoloaded on first call. The body of any
function can be inspected with `declare -f`:

    `declare -f split`     show the implementation of `split`

Reading these implementations can provide good examples of idiomatic
shed scripting. They exercise quoting, error handling,
parameter expansion, and shed-specific builtins like |quote| and
|raise| in real, working code rather than synthetic examples.

For the language reference on writing your own functions, see
|script-functions|(script-functions).

The following functions are bundled:

  `logout`      exit a login shell                           |function-logout|
  `qcount`      count records or fields in a quoted stream   |function-qcount|
  `qmap`        transform each record via a lambda           |function-qmap|
  `qname`       prepend a header record to a stream          |function-qname|
  `qpad`        normalize records to uniform field count     |function-qpad|
  `qpipe`       pipe each record through an external command |function-qpipe|
  `qselect`     project or reorder fields in records         |function-qselect|
  `qtable`      render a quoted stream as a table            |function-qtable|
  `qwhere`      filter records by a predicate                |function-qwhere|
  `split`       split a string by a pattern                  |function-split|
  `version`     print the shed version                       |function-version|

Quoted Stream Adapters ~                                  *quoted-streams*

  The `q`-prefixed functions (`qmap`, `qwhere`, `qselect`, `qpad`,
  `qcount`, `qpipe`, `qtable`) operate on streams of shell-quoted
  records. A "quoted stream" is a byte stream where:

    - records are separated by newlines
    - fields within a record are separated by whitespace
    - field contents are encoded with |quote|(builtin-quote) (single
      quotes for whitespace, ANSI-C for control characters, bare
      for plain identifiers)
    - empty fields are encoded as `''`

  Producers (|split|(function-split), |quote|(builtin-quote)) emit
  streams in this format. Consumers (these `q`-adapters,
  |unquote|(builtin-unquote), `read -q`) decode them. The format is
  byte-compatible with line-oriented Unix tools like `sort`, `head`,
  `tail`, `uniq`, and `wc`, which means quoted streams pipe through
  the standard toolchain without adapters.

  See |builtin-quote| and |builtin-unquote| for encoding details.

Named streams ~                                          *named-streams*

  |qname|(function-qname) builds a named stream by prepending a header
  record to its input. From there, several adapters accept `-n` to
  treat that first record as a header naming each field. With `-n`:

    - |qcount|(function-qcount) skips the header before counting
    - |qmap|(function-qmap) binds each field by its header name as a
      local in the lambda, and re-emits the header unchanged
    - |qwhere|(function-qwhere) binds each field by its header name in
      the predicate, and passes the header through unfiltered
    - |qselect|(function-qselect) lets you project fields by name as
      well as by index, and rewrites the header to match
    - |qpad|(function-qpad) keeps the header as the first record and
      pads it alongside the body to the common field count
    - |qtable|(function-qtable) uses the header as the table's column
      titles

  A named stream is an ordinary quoted stream; the header is just its
  first record. Tools that are unaware of `-n` pass it through as data.

==============================================================================
LOGOUT                                           *function-logout* *logout*

  `logout`

  Exit the current shell, but only if it's a login shell. Errors with
  exit status 2 otherwise.

  A shell is considered a login shell when its `$0` begins with `-`,
  which is the convention by which a parent process indicates the
  session was started as a login.

  Examples:

      `logout`           exit if this is a login shell

==============================================================================
QCOUNT                                           *function-qcount* *qcount*

  `qcount [-f] [-n]`

  Count records in a quoted stream, or fields per record.

  `-f`    print the number of fields in each record, one count per
          line. Useful for sanity-checking that a stream has the
          shape you expect.

  `-n`    treat the first record as a header and skip it, so it is
          not counted. See |named-streams|.

  Without `-f`, prints a single number: the total record count
  consumed from stdin.

  Examples:

      `producer | qcount`                count records
      `producer | qcount -f`             field count per record
      `producer | qcount -n`             count records, ignoring header
      `producer | qcount -f | sort -u`   inspect record shapes
                                         (one unique line means a
                                         uniform stream)

  See also: |quoted-streams|, |named-streams|, |function-qpad|

==============================================================================
QMAP                                             *function-qmap* *qmap*

  `qmap [-n] {body}`

  Transform each record in a quoted stream by running {body} as a
  shell lambda. Fields of the current record are bound as `$1`, `$2`,
  ..., `$@`. Whatever {body} writes to stdout becomes downstream
  content; re-encode with |quote|(builtin-quote) to emit a properly-
  encoded record.

  {body} is interpreted as a shell script string. Each invocation
  runs in its own function scope so `return` returns from the lambda
  rather than from `qmap`, and `local` declarations inside the body
  do not leak between records.

  `-n`    treat the first record as a header. Each field is bound as
          a local named after its column in addition to the positional
          `$1`, `$2`, ..., and the header is re-emitted unchanged ahead
          of the transformed records. See |named-streams|.

  Examples:

      `producer | qmap 'quote "$1" "extra"'`
                          append a literal field to every record

      `producer | qmap 'quote "${1^^}"'`
                          uppercase the first field

      `producer | qmap 'quote "$2" "$1"'`
                          swap fields 1 and 2 (assumes 2-field input)

      `producer | qmap -n 'quote "$name" "$size"'`
                          reference fields by their header names

      `producer | qmap 'quote "$(realpath "$1")"'`
                          resolve path in field 1 to its absolute form

  See also: |quoted-streams|, |named-streams|, |function-qwhere|

==============================================================================
QNAME                                            *function-qname* *qname*

  `qname {name} [{name} ...]`

  Prepend a header record to a quoted stream. Each {name} becomes one
  field of a header record emitted ahead of the input, turning a plain
  stream into a named stream (see |named-streams|). The names are
  encoded with |quote|(builtin-quote) like any other record, and the
  original input follows unchanged.

  This is the producer side of the `-n` convention: downstream
  adapters invoked with `-n` will treat the record `qname` emits as
  the header.

  The whole stream is buffered so the header can be emitted first.

  Examples:

      `producer | qname name size user`
                          label a three-field stream

      `producer | qname name size user | qtable -n`
                          name the columns, then render with headings

      `producer | qname name size | qwhere -n '[ "$size" -gt 0 ]'`
                          name the columns, then filter by name

  See also: |quoted-streams|, |named-streams|, |function-qtable|

==============================================================================
QPAD                                             *function-qpad* *qpad*

  `qpad [-n]`

  Normalize a quoted stream so every record has the same number of
  fields. Reads the entire stream, finds the longest record, then
  emits all records padded to that length with empty fields (`''`).

  Useful upstream of |qselect|(function-qselect) to make
  field projection safe: with a padded stream, indices that would
  otherwise overflow short records yield empty strings rather than
  errors.

  `-n`    treat the first record as a header. It is included when
          finding the longest record and padded along with the body,
          so the header always has a slot per column. See
          |named-streams|.

  Note: this operator must buffer the entire stream in memory to find
  the longest record. Not suitable for unbounded producers.

  Examples:

      `producer | qpad`                  normalize record shape
      `producer | qpad | qselect 1 3`    safe projection even when
                                         some records had <3 fields
      `producer | qpad -n | qtable -n`   pad a named stream, then
                                         render it as a table
      `producer | qpad | qcount -f \\`
        `| sort -u`                      should print exactly one
                                         number after padding

  See also: |quoted-streams|, |named-streams|, |function-qselect|,
  |function-qcount|

==============================================================================
QPIPE                                            *function-qpipe* *qpipe*

  `qpipe [-n] {command} [{arg} ...]`

  Pipe each record through an external {command}, one record at a
  time. The fields of the record are written to the command's stdin,
  one field per line, and the command's output lines are collected
  and re-encoded as a single quoted record via |quote|(builtin-quote).

  This bridges quoted streams to line-oriented tools that operate
  within a record rather than across the whole stream. Because each
  record spawns the command afresh, qpipe is best for light filters,
  not high-volume streams.

  `-n`    treat the first record as a header and re-emit it ahead of
          the transformed records. See |named-streams|.

  Examples:

      `producer | qpipe sort`            sort the fields within each
                                         record

      `producer | qpipe grep -v '^$'`    drop empty fields from each
                                         record

      `producer | qpipe tr a-z A-Z`      uppercase every field

  See also: |quoted-streams|, |named-streams|, |function-qmap|

==============================================================================
QSELECT                                          *function-qselect* *qselect*

  `qselect [-n] {idx|name} [{idx|name} ...]`

  Project and/or reorder fields in each record. Fields are 1-indexed.
  Indices may be repeated; the resulting record has fields in exactly
  the order specified.

  Errors with exit status 1 if any requested index is `0`, or if any
  index exceeds the field count of a record being processed. To make
  projection safe for variable-shape streams, pipe through
  |qpad|(function-qpad) first.

  `-n`    treat the first record as a header. Arguments may then be
          column names as well as numeric indices, and the header is
          rewritten to the selected columns. A name that matches no
          column errors with exit status 1. See |named-streams|.

  Examples:

      `producer | qselect 1`             keep only field 1
      `producer | qselect 2 1`           swap fields 1 and 2
      `producer | qselect 1 1 1`         emit field 1 three times
      `producer | qselect 3 1`           keep fields 3 and 1 in that
                                         order, drop field 2
      `producer | qselect -n name size`  project by column name
      `producer | qpad | qselect 3 1`    safe projection on padded
                                         stream

  See also: |quoted-streams|, |named-streams|, |function-qpad|

==============================================================================
QTABLE                                           *function-qtable* *qtable*

  `qtable [-n]`

  Render a quoted stream as a box-drawn table, one row per record and
  one column per field. Column widths are sized to the widest cell
  using |width|(builtin-width), so the layout stays aligned even with
  wide characters and combining marks.

  The whole stream is buffered before drawing, since column widths
  cannot be known until every record has been read. Not suitable for
  unbounded producers.

  `-n`    treat the first record as a header and render it as the
          table's column titles, separated from the body by a rule.
          When the table is taller than the terminal the header is
          repeated at the bottom. See |named-streams|.

  Examples:

      `producer | qtable`                render records as a table

      `producer | qtable -n`             use the first record as
                                         column headings

  See also: |quoted-streams|, |named-streams|, |builtin-width|

==============================================================================
QWHERE                                           *function-qwhere* *qwhere*

  `qwhere [-n] {predicate}`

  Filter records in a quoted stream. {predicate} is a shell lambda
  evaluated per record with fields bound as `$1`, `$2`, etc. Records
  where the predicate exits 0 are passed through unchanged; records
  where it exits non-zero are dropped. The original quoted record
  is emitted byte-for-byte on a match.

  The predicate runs in its own function scope.

  `-n`    treat the first record as a header. Each field is also bound
          as a local named after its column, so the predicate can refer
          to fields by name, and the header is passed through
          unfiltered. See |named-streams|.

  Inspired by `where` in `nushell`, but evaluates an arbitrary shell
  expression rather than a typed comparison.

  Examples:

      `producer | qwhere '[ "$1" = "active" ]'`
                          keep records where field 1 equals "active"

      `producer | qwhere '[ -f "$1" ]'`
                          keep records whose first field names an
                          existing file

      `producer | qwhere '[[ "$1" == git* ]]'`
                          glob match on field 1

      `producer | qwhere -n '[ "$size" -gt 10 ]'`
                          filter by a named column

      `producer | qwhere '[ "${#1}" -gt 10 ]'`
                          keep records where field 1 is longer than
                          10 characters

  See also: |quoted-streams|, |named-streams|, |function-qmap|

SPLIT                                            *function-split* *split*

  `split {pattern} {string}`
  `cmd | split {pattern}`
  `cmd | split -0`

  Split input on every occurrence of {pattern} and emit each part
  through |quote|(builtin-quote). The output is a quoted record
  stream suitable for decoding/formatting via |unquote|(builtin-unquote),
  or for consumption by the `q`-prefixed adapter functions (see |quoted-streams|).

  Trailing delimiters are stripped before splitting, so an empty
  final field is never produced. An empty {string} produces no output.

  `-0`    use the NUL byte as the delimiter. Equivalent to passing
          `$'\0'` as the pattern. Designed to pair with `find -print0`
          and other NUL-emitting tools.

  Input modes ~

    With both {pattern} and {string} as arguments, splits {string}
    once and exits.

    With only {pattern} (or `-0`) and data piped on stdin, reads each
    input line and splits each independently. Each input line becomes
    one or more output records depending on how many parts the
    pattern produces.

  Examples:

      `split : "$PATH" | unquote -a paths`
                                split `PATH` into `$paths`, preserving
                                structure of paths containing whitespace

      `split , "a,b,c" | unquote`
                                prints `a`, `b`, `c` on three lines

      `split "->" "x->y->z" | unquote -a chain`
                                multi-character delimiter, into an array

      `find . -print0 | split -0 | unquote -0 | xargs -0 ...`
                                bridge `find -print0` into shed's
                                quoted-stream protocol and back to
                                a NUL-aware external consumer

      `cat config.txt | split = | qwhere '[ "$1" = "some_key" ]'`
                                stream mode: each line of the file
                                is split on `=`, then filtered

  See also: |quote|(builtin-quote), |unquote|(builtin-unquote),
  |quoted-streams|

==============================================================================
VERSION                                          *function-version* *version*

  `version [-v]`

  Print the shed version. Without options, prints the semantic version
  (e.g. `0.28.1`). With `-v`, prints the full version triple including
  architecture and operating system.

  Examples:

      `version`            outputs:  `0.28.1`
      `version -v`         outputs:  `shed v0.28.1 (x86_64 linux)`
