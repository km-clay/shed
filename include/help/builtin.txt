*builtin* *builtins* *builtin-commands*

#BUILTIN COMMANDS#

Builtins are commands implemented directly by the shell rather than as
external executables. They have access to shell state (variables, job table, etc.) that external commands cannot reach.

The following builtins are available:

  `alias`       define or list command aliases              |builtin-alias|
  `arrops`      array manipulation (push, pop, rotate)      |builtin-arrops|
  `autocmd`     register hooks for shell events             |builtin-autocmd|
  `bg`          resume a stopped job in the background      |builtin-bg|
  `cd`          change the working directory                |builtin-cd|
  `compadd`     register completion candidates              |builtin-compadd|
  `compgen`     emit completion candidates                  |builtin-compgen|
  `complete`    define custom tab completion rules          |builtin-complete|
  `declare`     declare variables with type and attributes  |builtin-declare|
  `dirs`        display the directory stack                 |builtin-dirs|
  `disown`      remove a job from the job table             |builtin-disown|
  `echo`        print arguments to stdout                   |builtin-echo|
  `eval`        evaluate a string as shell input            |builtin-eval|
  `exec`        replace the shell process with a command    |builtin-exec|
  `exit`        exit the shell                              |builtin-exit|
  `export`      mark variables for export to environment    |builtin-export|
  `false`       return exit status 1                        |builtin-false|
  `fc`          edit and re-exec commands from history      |builtin-fc|
  `flog`        write a formatted log message               |builtin-flog|
  `fg`          bring a job to the foreground               |builtin-fg|
  `genrc`       (re)generate the rc file from live state    |builtin-genrc|
  `getopts`     parse option flags in scripts               |builtin-getopts|
  `hash`        manage the command location cache           |builtin-hash|
  `help`        display help pages                          |builtin-help|
  `hist`        query and manage shell history              |builtin-hist|
  `jobs`        list background jobs                        |builtin-jobs|
  `keymap`      define custom key bindings                  |builtin-keymap|
  `kill`        send signals to processes                   |builtin-kill|
  `local`       declare variables local to a function       |builtin-local|
  `msg`         post a message to the status bar            |builtin-msg|
  `popd`        pop the directory stack                     |builtin-popd|
  `printf`      formatted output                            |builtin-printf|
  `pushd`       push a directory onto the stack             |builtin-pushd|
  `pwd`         print the working directory                 |builtin-pwd|
  `quote`       shell-quote arguments for round-tripping    |builtin-quote|
  `read`        read a line of input into a variable        |builtin-read|
  `readkey`     read a single keypress                      |builtin-readkey|
  `readonly`    mark variables as read-only                 |builtin-readonly|
  `return`      return from a function                      |builtin-return|
  `break`       exit a loop                                 |builtin-break|
  `continue`    skip to the next loop iteration             |builtin-continue|
  `raise`       raise a user-facing error from a function   |builtin-raise|
  `seek`        seek a file descriptor to a byte offset     |builtin-seek|
  `set`         set shell options and positional parameters |builtin-set|
  `stash`       save and recall command snippets            |builtin-stash|
  `shift`       shift positional parameters                 |builtin-shift|
  `shopt`       get or set shell options                    |builtin-shopt|
  `source`      execute a file in the current shell         |builtin-source|
  `[[`          evaluate conditional expressions            |builtin-test|
  `thru`        pass stdin to stdout, optionally tee/limit  |builtin-thru|
  `times`       print shell and child CPU times             |builtin-times|
  `trap`        set signal handlers                         |builtin-trap|
  `true`        return exit status 0                        |builtin-true|
  `type`        describe how a name would be interpreted    |builtin-type|
  `ulimit`      set process resource limits                 |builtin-ulimit|
  `umask`       set the file creation mask                  |builtin-umask|
  `unalias`     remove aliases                              |builtin-unalias|
  `unquote`     decode shell-quoted input into fields       |builtin-unquote|
  `unset`       remove variables or functions               |builtin-unset|
  `wait`        wait for background jobs to finish          |builtin-wait|
  `width`       print the display width of a string         |builtin-width|

ALIAS                                            *builtin-alias* *alias*

  `alias [name[=value] ...]`

  With no arguments, lists all defined aliases in alphabetical order,
  in the form `name="value"`. Alias definitions printed this way are
  valid shell input that can be reused to recreate the alias.

  With arguments of the form `name=value`, defines an alias. When
  {name} is used as a command, it is replaced with {value} before
  execution. Multiple aliases can be defined in a single call.

  Alias expansion occurs very early in the execution process.

  With an argument that has no `=`, prints the current definition of
  that alias.

  The names `command` and `builtin` are reserved and cannot be aliased.

  Examples:

      `alias`                           list all aliases
      `alias ll='ls -la'`               define an alias
      `alias ll`                        print: ll='ls -la'
      `alias g='git' gs='git status'`   define multiple

==============================================================================
UNALIAS                                          *builtin-unalias* *unalias*

  `unalias [name ...]`

  Remove the named aliases. With no arguments, lists all defined
  aliases (same as `alias` with no arguments).

  It is an error to unalias a name that is not currently defined.

  Examples:

      `unalias ll`               remove the ll alias
      `unalias g gs`             remove multiple aliases

ARROPS                                           *builtin-arrops* *arrops*

  Array operation builtins for manipulating shell |arrays|. All commands
  share a common set of options:

    `-c {n}`     perform the operation {n} times (default: 1)
    `-v {var}`   store the result in {var} instead of printing to stdout
                 (pop/fpop only)
    `-r`         reverse direction (rotate only)

  PUSH                                           *builtin-push* *push*

  `push {array} {value} ...`

      Append one or more values to the back of {array}. If {array}
      does not exist, it is created. Multiple values are appended
      left to right.

      Examples:
          `push myarr a b c`     append a, b, c to the back

  FPUSH                                          *builtin-fpush* *fpush*

  `fpush {array} {value} ...`

      Prepend one or more values to the front of {array}. Each value
      is pushed to the front sequentially, so the last value ends up
      at index 0.

      Example:
          `fpush arr a b`    given arr=[c], result is [b, a, c]

  POP                                            *builtin-pop* *pop*

  `pop [-c {n}] [-v {var}] {array}`

      Remove and print the last element of {array}. With `-c`, removes
      that many elements from the back, printing each on its own line.
      With `-v`, stores the popped value in {var} instead of printing.

      Sets exit status 1 if the array is empty or does not exist.

      Examples:
          `pop myarr`            print and remove last element
          `pop -c 2 myarr`       remove and print last 2 elements
          `pop -v x myarr`       store last element in $x

  FPOP                                           *builtin-fpop* *fpop*

  `fpop [-c {n}] [-v {var}] {array}`

      Remove and print the first element of {array}. Equivalent to
      `pop` but operates on the front of the array.

      Examples:
          `fpop myarr`           print and remove first element
          `fpop -c 2 myarr`      remove and print first 2 elements
          `fpop -v x myarr`      store first element in $x

  ROTATE                                         *builtin-rotate* *rotate*

  `rotate [-c {n}] [-r] {array}`

      Rotate {array} left by {n} positions (default: 1). With `-r`,
      rotate right instead. If {n} exceeds the array length it is
      clamped, making a full rotation a no-op.

      Examples:
          `rotate arr`           [a,b,c,d] -> [b,c,d,a]
          `rotate -c 2 arr`      [a,b,c,d] -> [c,d,a,b]
          `rotate -r arr`        [a,b,c,d] -> [d,a,b,c]

AUTOCMD                                          *builtin-autocmd* *autocmd*

  `autocmd`
  `autocmd {event}`
  `autocmd [-c] {event} [{command}]`

  Register, clear, or list {command}s to run when {event} fires.
  Multiple commands can be registered for the same event; they run
  in registration order. The exit status of autocmd handlers does
  not affect `$?`.

  `-c`    clear all registered commands for {event} instead of adding one

  Listing ~

    With no arguments, prints every registered autocmd across all
    events. With a single {event} and no {command}, prints only
    the autocmds registered for that event:

        `autocmd`              list every registered autocmd
        `autocmd post-cmd`     list autocmds for the post-cmd event

  Available events:

    `pre-cmd`               before a command is executed
    `post-cmd`              after a command completes
    `on-command-not-found`  when command not found
    `pre-change-dir`        before `cd` changes the directory
    `post-change-dir`       after `cd` changes the directory
    `on-job-finish`         when a background job finishes
    `pre-prompt`            before the prompt is displayed
    `post-prompt`           after the prompt is displayed
    `pre-mode-change`       before the editor mode changes
    `post-mode-change`      after the editor mode changes
    `on-history-open`       when history search opens
    `on-history-close`      when history search closes
    `on-history-select`     when a history entry is selected
    `on-completion-start`   when tab completion starts
    `on-completion-cancel`  when tab completion is cancelled
    `on-completion-select`  when a completion candidate is selected
    `on-idle-timeout`       when the prompt has been idle past `prompt.idle_timeout`
    `on-time-report`        when a timed command reports its duration
    `on-exit`               when the shell exits

  Examples:

      `autocmd post-cmd 'echo done'`
      `autocmd post-change-dir 'ls'`
      `autocmd -c post-cmd`           clear all post-cmd handlers
      `autocmd`                       list all registered autocmds
      `autocmd post-cmd`              list autocmds for post-cmd

  For special variables available inside autocmd handlers, see |autocmd|.

BUILTIN                                          *builtin-builtin* *builtin-cmd*

  `builtin {name} [argument ...]`

  Execute the shell builtin named {name}, bypassing any function or
  alias of the same name. Useful when you have defined a function that
  wraps a builtin and want to call the underlying builtin from inside
  the wrapper without recursing.

  If {name} is not a recognized builtin, exits 127 with an error.

  The name `builtin` itself is reserved and cannot be shadowed by an
  alias.

  Examples:

      `cd() { builtin cd "$@" && ls; }`   wrap cd without recursing
      `builtin echo hello`                bypass any user-defined echo

==============================================================================
CD                                               *builtin-cd* *cd*

  `cd [-L|-P] [{dir}]`

  Change the working directory to {dir}. With no argument, changes to
  `$HOME`. Updates `$PWD` and `$OLDPWD`.

  `-L`    follow symbolic links (default)
  `-P`    resolve symbolic links to their physical (canonical) path

  Special arguments:

    `-`    change to `$OLDPWD` (the previous directory) and print the
           new path. Repeating `cd -` toggles between the two directories.

  `$CDPATH`

      A colon-separated list of directories to search when {dir} is a
      relative path that does not begin with `./`, or `../`. An
      empty entry in `$CDPATH` is treated as `.`.

  Fires the `pre-change-dir` and `post-change-dir` autocmd events.
  See |autocmd| for available hook variables.

  Examples:

      `cd`                  go to $HOME
      `cd /tmp`             absolute path
      `cd -`                return to previous directory
      `cd -P ~/link`        resolve symlink before changing

COMMAND                                          *builtin-command* *command*

  `command [-p] {name} [argument ...]`
  `command [-v | -V] {name}`

  Execute {name} as a simple command, suppressing the shell function and
  alias lookup that would normally happen first. Useful when you have
  defined a function that shadows an external command and want to call
  the original from inside the function without recursing.

  With no options and no arguments, exits 0 silently.

  `-p`     Perform the command search using a system default `$PATH` that
           is guaranteed to find the standard POSIX utilities, even if the
           user's `$PATH` has been overridden or cleared. The override is
           scoped to this invocation only; the user's `$PATH` is restored
           afterwards.

  `-v`     Do not execute. Print how {name} would be resolved:
             - external command:   absolute pathname
             - shell builtin:      just the name
             - shell function:     just the name
             - shell keyword:      just the name
             - alias:              `alias name='definition'` form
             - not found:          no output, exit status 127

  `-V`     Do not execute. Print a human-readable description of how
           {name} would be interpreted:
             - external command:   `name is /usr/bin/name`
             - shell builtin:      `name is a shell builtin`
             - shell function:     `name is a function`
             - shell keyword:      `name is a shell keyword`
             - alias:              `name is an alias for 'definition'`
             - not found:          error to stderr, exit status 127

  `-v` and `-V` cannot be combined; passing both is an error.

  The name `command` itself is reserved and cannot be shadowed by an
  alias.

  Examples:

      `command ls`               run external ls, bypassing functions
      `command -p cat foo`       run cat from the system default $PATH
      `command -v git`           print the absolute pathname of git
      `command -v ll`            print: alias ll='ls -la'
      `command -V if`            print: if is a shell keyword
      `command -- -p`            treat -p as the command name, not a flag

COMPLETE                                         *builtin-complete* *complete*

  `complete [options] {cmd} ...`

  Register a tab completion specification for one or more commands. When
  the user presses Tab after {cmd}, the shell uses the registered spec to
  generate candidates. Multiple commands may be given; they all receive
  the same spec.

  Source Flags (what to complete) ~

    `-W {wordlist}`   complete from a static whitespace-separated word list
    `-F {func}`       call shell function {func} to generate candidates.
                      The function should populate `$COMPREPLY` with the
                      list of matches.
    `-A {action}`     complete from a built-in action name (see below)
    `-f`              complete file names
    `-d`              complete directory names
    `-c`              complete command names (executables and builtins)
    `-u`              complete user names
    `-v`              complete variable names
    `-a`              complete alias names
    `-j`              complete job names
    `-S`              complete signal names

  Behavior Flags ~

    `-o default`      fall back to default (filename) completion if the
                      spec produces no candidates
    `-o dirnames`     fall back to directory completion if no candidates
    `-o space`        append a space after a completed word (default)

  Management Flags ~

    `-p [{cmd} ...]`  print registered specs. With no {cmd}, prints all.
    `-r [{cmd} ...]`  remove the spec for each {cmd}.

  Examples:

      `complete -W 'start stop restart' myservice`
      `complete -F _git_complete git`
      `complete -f -d cp`
      `complete -p git`           print git's registered spec
      `complete -r git`           remove git's spec

  When `-F` is used, the following variables are set before the function
  is called and should be read (not modified) by the function:

    `$COMP_WORDS`     array of words on the current command line
    `$COMP_CWORD`     index of the word being completed
    `$COMP_LINE`      the full current command line as a string
    `$COMP_POINT`     cursor position within `$COMP_LINE`

  The function sets `$COMPREPLY` to an array of completion candidates.

COMPADD                                          *builtin-compadd* *compadd*

  `compadd [options] [{candidate} ...]`

  Add completion candidates to the current completion set. Intended for
  use inside completion functions registered with `complete -F`. Each
  positional argument is added as a candidate; the source flags below
  pull additional candidates from shell variables.

  Source flags ~

    `-a {name}`     add each element of the indexed array `{name}` as
                    a candidate.
    `-d {name}`     pair each candidate (in order) with one description
                    from the indexed array `{name}`. Extra descriptions
                    are dropped; missing descriptions leave the
                    candidate undescribed.
    `-A {name}`     add candidates from the associative array `{name}`,
                    using each key as a candidate and the corresponding
                    value as its description. Insertion order is
                    preserved. Pairing is intrinsic to the array, so it
                    cannot fall out of sync the way parallel `-a`/`-d`
                    arrays can.

  Decoration flags ~

    `-P {prefix}`   prepend `{prefix}` to every candidate's text. Does
                    not affect descriptions.
    `-S {suffix}`   append `{suffix}` to every candidate's text. Does
                    not affect descriptions.

  Sources are additive: positional arguments, `-a`, and `-A` can all be
  passed in a single call and their candidates concatenate. `-P` and
  `-S` apply to candidates from every source.

  Lookups for `-a`, `-d`, and `-A` silently contribute nothing if the
  named variable is unbound or has the wrong kind, so a stray bad name
  in a completion function won't break the rest of the completion.

  Examples:

      `compadd alpha beta gamma`
                  three plain candidates with no descriptions

      `local -a words=(start stop restart)`
      `compadd -a words`
                  candidates from an indexed array

      `local -a words=(a b c) descs=(first second third)`
      `compadd -a words -d descs`
                  parallel arrays, first/second/third describe a/b/c

      `local -A modes=([n]=normal [i]=insert [v]=visual)`
      `compadd -A modes`
                  candidates n/i/v with their respective descriptions,
                  in insertion order

      `local -A modes=([n]=normal [i]=insert)`
      `compadd -P "-" -A modes`
                  produces -n and -i with descriptions preserved
                  (typical pattern for completing short flags with
                  human-readable hints)

  See |builtin-complete| for registering a completion function and
  |builtin-compgen| for generating candidates standalone.

==============================================================================
COMPGEN                                          *builtin-compgen* *compgen*

  `compgen [options] [{prefix}]`

  Generate completion candidates without registering a spec. Applies the
  given source flags against {prefix} (if provided) and prints one
  candidate per line. Useful for testing completion logic or inside `-F`
  functions.

  Accepts the same source flags as `complete` (`-W`, `-F`, `-f`, `-d`,
  `-c`, `-u`, `-v`, `-a`, `-j`, `-S`, `-o`).

  Examples:

      `compgen -W 'foo bar baz'`        print all three words
      `compgen -W 'foo bar baz' b`      print only: bar baz
      `compgen -f /tmp/`                list files under /tmp/
      `compgen -v HOME`                 list variables starting with HOME
      `compgen -F _my_func`             run function and print results
      `compgen -o default`              fall back to default completion

DECLARE                                          *builtin-declare* *declare*

  `declare [-aAirx] [name[=value] ...]`
  `declare -p [name ...]`
  `declare -f [name ...]`
  `declare -F [name ...]`

  Declare variables, optionally setting their type and attributes in
  the same step. With no flags and a `name=value` argument, behaves
  like a plain assignment. Combined with `-a`, `-A`, `-i`, `-r`, or
  `-x`, fixes the variable's type and/or attributes at declaration
  time.

  With no arguments and no introspection flag, lists all variables in
  the current scope as `declare`-syntax assignments suitable for
  re-execution.

  Type flags ~

    `-a`    indexed array. RHS may be `(elem1 elem2 ...)`
    `-A`    associative array. RHS may be `([key1]=v1 [key2]=v2 ...)`.
            Insertion order is preserved, which makes assoc arrays the
            natural source for completion candidates with descriptions
            via `compadd -A`. See |builtin-compadd|.
    `-i`    integer. RHS is arithmetic-evaluated, so `declare -i x=5+3`
            stores `8`. Subsequent assignments are also evaluated.

  Only one type flag may be given per call. Without a type flag, the
  variable is a string.

  Attribute flags ~

    `-r`    read-only. Equivalent to `readonly`. Cannot be reassigned
            or unset. See |builtin-readonly|.
    `-x`    export. Equivalent to `export`. Marks the variable for
            propagation to child processes. See |builtin-export|.

  Type and attribute flags can be combined: `declare -ix N=10` makes
  `N` an integer that is also exported.

  Introspection flags ~

    `-p`    print all variables (or only the named ones) as
            `declare`-syntax assignments. Suitable for re-execution.
    `-f`    print all functions (or only the named ones) including
            their bodies, as parseable function definitions.
    `-F`    print only the function names (or only the named ones),
            one per line in the form `declare -f {name}`. Useful for
            checking whether a function is defined without dumping its
            body.

  Introspection flags are mutually exclusive with each other and with
  type/attribute flags.

  Scope ~

  `declare` operates on the current scope, the same way |builtin-local|
  does. Inside a function or brace group, the variable is local to
  that scope and is discarded when the scope exits. At the top level,
  it is global.

  Examples:

      `declare`                       list all variables in scope
      `declare x=10`                  string variable
      `declare -i n=5+3`              integer, evaluates to 8
      `declare -a arr=(a b c)`        indexed array
      `declare -A m=([k1]=v1 [k2]=v2)` associative array
      `declare -rx PATH`              mark existing var read-only and exported
      `declare -p PATH`               print PATH as a declare statement
      `declare -F`                    list all defined function names
      `declare -f my_func`            print the body of my_func

  See also: |builtin-local|, |builtin-export|, |builtin-readonly|,
  |builtin-unset|.

DIRS                                             *builtin-dirs* *dirs*

  `dirs [-clpv] [+N | -N]`

  Display the directory stack. The current working directory is always
  at the top (index 0); entries pushed by `pushd` follow.

  `-c`       clear the directory stack
  `-l`       show full paths. Do not abbreviate `$HOME` as `~`
  `-p`       print one entry per line
  `-v`       print one entry per line, preceded by its stack index
  `+N`       print only the entry at position N from the top (0-based)
  `-N`       print only the entry at position N from the bottom

  With no arguments, prints all entries on one line separated by spaces,
  abbreviating `$HOME` as `~`.

  Examples:

      `dirs`              list the full directory stack
      `dirs -v`           list with numeric indices
      `dirs +0`           print only the current directory
      `dirs -c`           clear the stack

ECHO                                             *builtin-echo* *echo*

  `echo [-n] [-e] [-E] [-p] [arg ...]`

  Write {arg}s to standard output, separated by spaces, followed by a
  newline.

  `-n`    suppress the trailing newline
  `-e`    interpret backslash escape sequences (see below)
  `-E`    disable escape interpretation (overrides `xpg_echo`)
  `-p`    expand each argument as a prompt string (see |prompt|)

  Escape sequences (active with `-e` or when `shopt core.xpg_echo=true`):

    `\n`     newline
    `\t`     horizontal tab
    `\r`     carriage return
    `\a`     alert (bell)
    `\b`     backspace
    `\e`     escape character (ESC)
    `\\`     literal backslash
    `\xNN`   byte with hex value NN (up to 2 digits)
    `\0NNN`  byte with octal value NNN (up to 3 digits)

  By default escape sequences are NOT interpreted. Set
  `shopt core.xpg_echo=true` to change this globally; `-E` opts out.

  Examples:

      `echo hello world`
      `echo -n no newline`
      `echo -e 'line1\nline2'`

==============================================================================
EVAL                                             *builtin-eval* *eval*

  `eval [arg ...]`

  Join all {arg}s with spaces and execute the result as shell input in
  the current environment. Variable assignments, function definitions,
  and other side effects persist after `eval` returns.

  With no arguments, succeeds silently.

  Examples:

      `eval echo hello`
      `eval 'x=42; echo $x'`
      `cmd='echo evaluated'; eval $cmd`

==============================================================================
EXEC                                             *builtin-exec* *exec*

  `exec [command [arg ...]]`

  Replace the current shell process with {command}. On success `exec`
  does not return. The shell is replaced entirely.

  With no arguments, succeeds silently (useful for applying redirections
  to the current shell without replacing it).

  It is an error if {command} cannot be found or executed.

  Examples:

      `exec /bin/sh`
      `exec myprogram arg1`

==============================================================================
EXIT                                             *builtin-exit* *exit*

  `exit [n]`

  Exit the shell with status {n}. If {n} is omitted, exits with status
  0. {n} must be a decimal integer.

  Examples:

      `exit`        exit with current status
      `exit 0`      exit successfully
      `exit 1`      exit with failure

==============================================================================
EXPORT                                           *builtin-export* *export*

  `export [name[=value] ...]`

  Mark variables for automatic export to the environment of subsequently
  executed commands. With `name=value`, sets and exports in one step.
  With just {name}, marks an existing variable as exported.

  With no arguments, lists all current environment variables
  alphabetically as `name="value"` pairs.

  Examples:

      `export`                  list all environment variables
      `export PATH`             export an existing variable
      `export EDITOR=nvim`      set and export
      `export A=1 B=2`          multiple in one call

FC                                               *builtin-fc* *fc*

  `fc [-e editor] [-nlrs] [first [last]]`
  `fc -s [old=new] [first]`

  Operate on history entries. {first} and {last} select a range and can
  be a history number, a negative offset from the most recent entry
  (e.g. `-2`), or a string prefix matching a command.

  Options ~

    `-e {editor}`   open selected entries in {editor} for editing, then
                    re-execute. Uses `$FCEDIT` or `$EDITOR` if not given.
    `-l`            list entries instead of editing. Defaults to the
                    most recent 16 entries when no range is given.
    `-n`            suppress line numbers in `-l` output
    `-r`            reverse the order of selected entries
    `-s [old=new]`  re-execute without opening an editor. If `old=new`
                    is given, substitute {old} with {new} first.

  After an edit session, if the command changed it is appended to
  history; if unchanged it is not. Per POSIX, `fc` itself is not
  recorded in history when it edits and re-executes a command.

  Examples:

      `fc -l`                   list last 16 commands
      `fc -l 1 10`              list entries 1-10
      `fc -s echo`              re-exec last command starting with "echo"
      `fc -s cat=dog`           re-exec with cat -> dog substitution
      `fc -e vim`               edit last command in vim

FLOG                       *builtin-flog* *flog* *FLOG_FMT* *flog-fmt*

  `flog [-p {prefix}] {level} {message} ...`

  Write a formatted log message to standard error. {level} must be one
  of `error`, `warn`, `info`, `debug`, or `trace` (case-insensitive).
  All remaining arguments after {level} are joined with spaces to form
  the message body.

  `-p {prefix}` / `--prefix {prefix}`

      Format string for the prefix that appears before the message.
      Supports two classes of placeholders:

      Named placeholders (expanded first) ~

        `{level}`    log level label, styled with color
        `{source}`   name of the source file or `<stdin>`
        `{line}`     line number of the `flog` call in the source
        `{col}`      column of the `flog` call in the source

      Date/time codes (expanded second, via strftime conventions) ~

        `%H`  hour (24-hour clock, 00-23)
        `%M`  minute (00-59)
        `%S`  second (00-60)
        `%Y`  4-digit year
        `%m`  month (01-12)
        `%d`  day of month (01-31)

      Any strftime format code accepted by chrono is valid.

  The `FLOG_LEVEL` environment variable controls the minimum level that
  produces output. A call whose level is below `FLOG_LEVEL` is silently
  suppressed. This allows scripts to emit `debug` or `trace` calls that
  are invisible by default and enabled on demand.
  The hierarchy is as follows:

        `none` > `error` > `warn` > `info` > `debug` > `trace`.

  A `FLOG_LEVEL` value of `none` suppresses all log messages.

  The `FLOG_FMT` environment variable sets the default prefix format
  used when `-p` is not specified. The `-p` flag takes precedence
  over `FLOG_FMT` if both are present. If neither is set, the prefix
  defaults to `[{level}]`. Useful for setting a project-wide log
  format once in `.shedrc` rather than passing `-p` to every call.

  Examples:

      `flog info "starting up"`
      `flog -p '[%H:%M:%S {level}]' warn "disk usage high"`
      `flog -p '[{level} {source}:{line}]' error "unexpected value"`
      `FLOG_LEVEL=debug flog debug "entering loop"`
      `FLOG_FMT='[%H:%M:%S {level}]' flog info "started"`
      `export FLOG_FMT='[{level} {source}:{line}]'  # in .shedrc`

GENRC                                            *builtin-genrc* *genrc*

  `genrc [-saAkfc] [--default] [--no-comments]`

  Print an rc file built from the current shell state to stdout. Useful
  for regenerating `~/.shedrc`, or for inspecting the live configuration
  in a re-sourceable form.

  By default, `genrc` dumps the *live* state: current `shopt` values,
  registered aliases, defined functions, registered autocmds, keymaps,
  and completion specs. Each output line is a shell command that, when
  sourced, would re-establish the corresponding piece of configuration.

  Section order in the output is shopts, aliases, functions,
  completions, autocmds, keymaps -- chosen so that later sections can
  safely reference symbols defined by earlier ones (e.g. a

  Note: emitted functions will include all of the builtin completion functions.

  `-s`                  Include the shopts section.
  `-a`                  Include the aliases section.
  `-A`                  Include the autocmds section.
  `-k`                  Include the keymaps section.
  `-f`                  Include the functions section.
  `-c`                  Include the completions section.

  `--default`           Emit factory-default shopt values and the canned
                        example autocmds, keymaps, and completion lines
                        instead of the live state. Matches the rc file
                        that shed generates on first run. Aliases and
                        functions are skipped in this mode (no canned
                        examples).

  `--no-comments`       Strip the header banner, per-section labels, and
                        trailing `# doc` annotations. Produces output
                        suitable for piping into `source` or for diffs.

  Examples:

      `genrc > ~/.shedrc.new`             snapshot current config
      `genrc --default > ~/.shedrc`       reset to factory defaults
      `genrc -Ak`                         pull just autocmds and keymaps
      `genrc -fa > ~/.shed_funcs.sh`      export functions and aliases
      `genrc -s --no-comments`            bare shopt dump, sourceable

HIST                                             *builtin-hist* *hist*

  `hist [options] [id ...]`

  Query and manage shell history. History is stored in a SQLite
  database and supports rich filtering. With no arguments or IDs,
  prints the full history oldest-first.

  Filter Options ~

    `--after {date}`          entries after {date} (natural language)
    `--before {date}`         entries before {date}
    `--contains {str}`        entries whose command contains {str}
    `--starts-with {str}`     entries whose command starts with {str}
    `--ends-with {str}`       entries whose command ends with {str}
    `--matches {regex}`       entries matching extended regex {regex}
    `--duration-gt {dur}`     entries with runtime longer than {dur}
    `--duration-lt {dur}`     entries with runtime shorter than {dur}
    `--lines-gt {n}`          entries with more than {n} lines
    `--lines-lt {n}`          entries with fewer than {n} lines
    `--with-status {code}`    entries whose command exited with {code}
    `--with-token {uuid}`     entries with the given unique token
    `--in-dir {path}`         entries run from {path} (exact match; "." expands)
    `--limit {n}`             return at most {n} results

  Any filter option can be negated by placing `--not` immediately before it:

      `hist --not --with-status 0`     commands that exited non-zero
      `hist --not --contains git`      commands not containing "git"
      `hist --not --in-dir .`          commands run outside current directory

  Output Options ~

    `-n`           suppress history IDs
    `-r`           newest-first order (default is oldest-first)
    `--count`      print only the count of matching entries
    `--json`       output as JSON (includes command, timestamp, runtime,
                   cwd, status, and token fields)

  Mutation Options ~

    `--delete`          delete matching entries
    `--restore`         restore previously deleted entries
    `--import {source}` import history from another shell (see below)
    `--ex`              operate on ex-mode history instead of shell command history

  Providing numeric arguments restricts results to those specific IDs:

      `hist 42 43`    print entries with IDs 42 and 43

  Dates accept natural language: "yesterday", "2 hours ago", "last
  monday", ISO 8601, etc. Durations: "5s", "2 minutes", "1 hour".

  Importing History ~

  `--import {source}` imports history from another shell's history file.
  {source} can be a shell name or an explicit file path:

    `bash`    ~/.bash_history   (plain text or with HISTTIMEFORMAT timestamps)
    `zsh`     ~/.zsh_history    (plain text or extended format)
    `fish`    ~/.local/share/fish/fish_history
    any path  treated as a file to auto-detect and import

  The format is detected automatically from the file contents. After import,
  entries are sorted by timestamp so imported history interleaves correctly
  with existing entries.

  Examples:

      `hist`                                    full history
      `hist --contains git`                     entries containing "git"
      `hist --after "yesterday"`                entries since yesterday
      `hist --limit 20 -n`                      last 20 commands, no IDs
      `hist --delete --contains foo`            delete entries containing "foo"
      `hist --not --with-status 0`              failed commands
      `hist --in-dir . --after "1 hour ago"`    recent commands in current dir
      `hist --import bash`                      import from ~/.bash_history
      `hist --import zsh`                       import from ~/.zsh_history
      `hist --import ~/old_history`             import from explicit path

LOCAL                                            *builtin-local* *local*

  `local [name[=value] ...]`

  Declare variables scoped to the current block. Local variables
  shadow any outer variable of the same name and are discarded when
  the enclosing scope exits. Unlike bash, where `local` only applies
  in functions, shed binds `local` to whatever scope frame is current.

  Scopes that hold `local` variables ~

    Function bodies                     variables die on function return
    Brace groups `{ ... }`              variables die on block exit

  declares with an empty value. Multiple declarations per call are
  allowed.

  Combine with |script-defer| for save-and-restore patterns: `local`
  captures the value, `defer` registers the restore, and both vanish
  together when the scope ends.

  Examples:

      `local x=10`
      `local a b c`
      `local`           list scope variables

PRINTF                                           *builtin-printf* *printf*

  `printf {format} [{argument} ...]`

  Format and print {argument}s according to the {format} string. Backslash
  escape sequences in {format} are interpreted; conversion specifiers
  beginning with `%` are replaced with formatted arguments.

  If there are more {argument}s than conversion specifiers in {format}, the
  format string is restarted from the beginning and applied repeatedly until
  all arguments are consumed. If there are fewer, missing numeric arguments
  default to 0 and missing string arguments default to the empty string.

  Conversion specifiers ~

  The general form of a conversion specifier is:

      `%[flags][width][.precision]conversion`

  Conversion characters:

    `%d`, `%i`    signed decimal integer
    `%u`          unsigned decimal integer
    `%o`          unsigned octal
    `%x`, `%X`    unsigned hexadecimal (lowercase / uppercase)
    `%f`          fixed-point decimal float (default precision 6)
    `%e`, `%E`    scientific notation (lowercase / uppercase exponent)
    `%g`, `%G`    shortest of `%f` or `%e`, with insignificant trailing
                  zeros removed
    `%c`          first character of the argument
    `%s`          string
    `%b`          string with backslash escapes interpreted (ANSI-C)
    `%q`          shell-quoted output suitable for re-input
    `%r`          repeat the argument string (shed extension). The field
                  width is the repeat count, not a pad width; see below
    `%(FORMAT)T`  date/time formatted via `strftime` codes. Argument is
                  seconds since the Unix epoch; `-1` means current time,
                  `-2` means shell start time
    `%%`          literal `%`

  `%r` is a `shed` extension; `bash` and `POSIX` do not provide it.

  Flags ~

    `-`           left-justify within field width (default is right-justify)
    `+`           always show sign on signed numeric output (`+42`, `-42`)
    `' '` (space) leave a space before positive numbers (` 42`)
    `#`           alternate form:
                    `%#o` prepends a `0` so the value reads as octal
                    `%#x` / `%#X` prepend `0x` / `0X` for non-zero values
                    `%#f`, `%#g` force a decimal point even with no
                    fractional digits
    `0`           zero-pad on the left instead of space-padding. Ignored
                  if `-` is also set, or for non-numeric conversions.

  Width and precision ~

    {width} is the minimum field width. Values shorter than {width} are
    padded; longer values are not truncated. A `*` in place of a number
    reads the width from the next argument.

    {precision} (preceded by `.`) means different things depending on the
    conversion:

      Integer:        minimum number of digits, zero-padded
      Float (`f e`):  digits after the decimal point (default 6)
      Float (`g`):    significant digits (default 6, minimum 1)
      String:         maximum characters to print

    A bare `.` is equivalent to `.0`. A `*` reads the precision from the
    next argument. A negative precision is treated as if absent.

    For `%r` the width slot is reinterpreted as a repeat count rather than
    a field width: the argument string is emitted that many times with no
    padding. `%5r` repeats five times, `%*r` takes the count from the next
    argument, and a bare `%r` (no count) emits a single copy. A count of
    `0` produces no output (only reachable via `%*r`, since a literal
    leading `0` is the zero-pad flag).

  Format-string escapes ~

  These backslash escapes are interpreted in the {format} string itself
  (separate from `%b` which interprets escapes in its argument):

    `\n` newline           `\t` tab                  `\r` carriage return
    `\\` backslash         `\a` alert (bell)         `\b` backspace
    `\f` form feed         `\v` vertical tab         `\e` escape (ESC)
    `\xNN`  byte with hex value NN (1-2 digits)
    `\NNN`  byte with octal value NNN (1-3 digits)

  Examples ~

      `printf 'hello %s\n' world`
                                outputs: `hello world`

      `printf '%s: %d\n' alice 1 bob 2 carol 3`
                                format restarts twice, outputs three lines

      `printf '[%5d] [%-5d] [%05d]\n' 42 42 42`
                                outputs: `[   42] [42   ] [00042]`

      `printf '%.3f\n' 3.14159`
                                outputs: `3.142`

      `printf '%.3s\n' hello`
                                outputs: `hel`

      `printf '%5r\n' =`
                                outputs: `=====`

      `printf '╭%*r╮\n' 4 '─'`
                                outputs: `╭────╮` (count from the argument;
                                handy for drawing rules and separators)

      `printf '%+d\n' 42`
                                outputs: `+42`

      `printf '%#x\n' 255`
                                outputs: `0xff`

      `printf '%q\n' 'hello world'`
                                outputs: `'hello world'` (round-trippable
                                through the shell parser)

      `printf '%(%Y-%m-%d)T\n' -1`
                                outputs the current date

      `printf '%(%H:%M:%S)T\n' -2`
                                outputs the shell start time

      `printf '%*d\n' 8 42`
                                width read from argument (width 8)

  See also: |builtin-echo|, |builtin-quote|

QUOTE                                            *builtin-quote* *quote*

  `quote [arg...]`

  Encode arguments as shell-quoted strings and print the results.
  Output uses the minimal quoting needed for each argument:

    - plain identifiers (no whitespace, shell metacharacters, or
      control characters) are emitted unchanged
    - arguments containing whitespace or shell metacharacters are
      emitted in single quotes (`'...'`), with embedded single quotes
      escaped as `'\''`
    - arguments containing control characters (newline, tab, etc.) are
      emitted as ANSI-C strings (`$'...'`) with backslash escapes
    - the empty string is emitted as `''`

  When data is piped to `quote` on standard input, the entire input is
  treated as a single value and encoded as one shell-quoted string.
  This is useful for round-tripping output from another command:

      `produce_data | quote | filter | unquote`

  When called with arguments instead, each argument is encoded
  independently and the results are joined by spaces. This is the
  natural form for emitting structured data from shell functions:

      `quote "${args[@]}"`

  All forms are bash-compatible, so the encoded output round-trips
  losslessly through any byte-clean pipe. Paired with |unquote|, this
  provides a pipeline-native serialization for shell data containing
  whitespace, newlines, quotes, or other characters that would
  otherwise be mangled by word-splitting or IFS expansion.

  Examples:

      `quote hello world`           outputs:  `hello world`
      `quote "hello world"`         outputs:  `'hello world'`
      `quote $'foo\nbar'`           outputs:  `$'foo\nbar'`
      `quote "${arr[@]}"`           encode each array element

      `echo "raw text" | quote`     encode stdin as one quoted string
      `quote "$(produce)" | filter | unquote`
      `result=$(quote "${args[@]}")`
      `eval "args=($result)"`       decode preserving structure

  See also: |unquote|(builtin-unquote)

UNQUOTE                                          *builtin-unquote* *unquote*

  `unquote [-v {name} | -a {name}] [-s {sep} | -0] [{input}]`

  Decode shell-quoted input and emit the original fields. Input is
  taken from standard input if anything is piped in, otherwise from
  the command-line arguments joined by spaces.

  With no target option, each decoded field is printed separated by
  the chosen field separator (newline by default). With `-v` or `-a`,
  fields are assigned to a variable instead and the separator options
  are ignored.

  Options:

    `-v {name}`, `--var {name}`     join decoded fields with spaces and
                                    assign to scalar variable {name}
    `-a {name}`, `--array {name}`   assign decoded fields as an array
                                    to {name}
    `-s {sep}`, `--sep {sep}`       use {sep} as the field separator in
                                    the output stream (default: newline)
    `-0`                            shorthand for `-s $'\0'`: separate
                                    fields with NUL bytes. Designed to
                                    pair with `xargs -0`, `sort -z`,
                                    `grep -z`, and other tools that
                                    consume NUL-separated input.

  The `-0` flag is the recommended way to bridge shed pipelines into
  the GNU `-0`-aware toolchain, since NUL is the only byte that can
  never appear in a filename or shell string. With `-s`, the output is
  emitted with NO trailing separator; with the default newline mode,
  a final newline is included for terminal-friendliness.

  Examples:

      `quote $'foo\nbar' | unquote`             round-trip; prints `foo`, `bar`
      `quote "${arr[@]}" | unquote -a out`      restore an array into $out
      `quote "$msg" | unquote -v decoded`       decode into a scalar
      `split : "$PATH" | unquote -a paths`      split `PATH`, preserving structure
                                              even if some paths have spaces

      `split : "$PATH" | unquote -0 | xargs -0 -I {} echo {}`
      `split , "$csv"   | unquote -s ','`       emit comma-joined values
      `produce | unquote -s ''`                 concatenate fields with no delimiter

  See also: |quote|(builtin-quote), |builtin-read| (for the `-q` flag)

READ                                             *builtin-read* *read*

  `read [-r] [-s] [-q] [-p {prompt}] [-d {delim}] [-a {array}] [name ...]`

  Read one line from standard input. The line is split by `$IFS` and
  assigned to {name}s in order. If there are more words than names,
  the last name receives the remainder. With no names, the result is
  stored in `$REPLY`.

  `-r`               raw mode: backslash is not an escape character
  `-s`               silent: do not echo typed characters
  `-q`, `--quoted`   parse input as shell-quoted fields instead of
                     splitting on `$IFS`. See "Quoted mode" below.
  `-p {prompt}`      display {prompt} before reading (no newline added)
  `-d {delim}`       read until {delim} byte instead of newline
  `-a {name}`        read all fields into array {name}
  `-n {bytes}`       read at most {bytes} bytes
  `-t {seconds}`     timeout after {seconds} of inactivity

  Quoted mode ~

    With `-q`, the input is parsed using shell-quoting rules instead of
    `$IFS`-based field splitting. Each input record (one line by default)
    is decoded as if it were a quoted shell value, and the resulting
    fields are assigned to {name}s in the same way as the default mode.

    Quoted mode is the consumer-side counterpart to |quote| and to
    output from commands like `printf %q`, `ls -Q --quoting-style=shell-escape`,
    or `declare -p`. It allows iterating over arbitrary structured data
    through a `while read` loop without the IFS hazards of the default
    mode. In particular, values containing spaces, newlines, or other
    characters that would normally collide with the field separator are
    preserved correctly as long as the producer emitted them in shell-
    quoted form.

    `-q` implies `-r`. Backslash escape processing happens at the lexer
    level inside `$'...'` sequences, not at the byte level.

  Examples:

    `read name`
    `read first rest`
    `read -p "Enter value: " x`
    `read -s password`

    `while read -q field; do                  iterate safely over
         echo "got: $field"                   shell-quoted input
     done < <(ls -Q --quoting-style=shell-escape)`

    `split : "$PATH" | while read -q path; do  walk PATH entries even
         echo "checking: $path"               if some contain spaces
     done                                     or newlines`

    `read -q -a fields                        decode all fields into
                                              array $fields`

  See also: |quote|(builtin-quote), |unquote|(builtin-unquote)

RAISE                                            *builtin-raise* *raise*

  `raise [-c | --code {n}] [-k | --kind {name}] [-n | --note {text}]... [message [args...]]`

  Raise an error from inside a function or sourced script. The error
  propagates upward through the call stack, eventually surfacing at
  the top level and pointing at the offending function call.

  Status (`$?`) is set to {n} upon being caught, either by `try` or
  surfacing at the top level.

  In contrast with `return 1`, errors created by `raise` use `shed`'s
  internal error reporting machinery, and they propagate upward until
  caught by a |try|(script-try) block, or reaching the top level.

  Options:

    `-c {n}`, `--code {n}`        Set the exit status to {n}. Defaults to 1.
    `-k {name}`, `--kind {name}`  Set the error's title to {name} instead
                                  of the default `"Raised Error"`.
    `-n {text}`, `--note {text}`  Attach a free-form note to the error.
                                  May be repeated to attach multiple notes,
                                  which render in order at the bottom of
                                  the error report.

  Format specifiers ~                                       *raise-format*

    The message can contain `%N` placeholders, where {N} is a digit
    sequence. Each `%N` consumes the next argument and renders it in
    the {N}th palette color. Multiple `%N` markers sharing the same
    {N} share the same color, so values that are semantically related
    can be visually linked even when their textual values differ.

    Use `%%` to insert a literal `%`. A trailing `%` with no following
    character is treated as a literal `%`.

    Examples (color shown as bracketed style):

      `raise "expected '%1', got '%2'" int string`
                      `----      ----  --- ------`
                       `int` and `string` are different colors

      `raise "removing '%1', '%1', and '%1'" main dev prod`
                      `----  ----      ----`
                       `main`, `dev`, and `prod` all share a color

  Examples:

      `logout() {`
      `  if [[ "$0" == -* ]]; then`
      `    exit 0`
      `  else`
      `    raise -c 2 "the current session is not a login shell"`
      `  fi`
      `}`

      `safe_cd() {`
      `  [[ -d "$1" ]] || raise --code 2 "not a directory: $1"`
      `  builtin cd "$1"`
      `}`

      `validate_port() {`
      `  local port="$1"`
      `  [ -i "$port" ] || raise "expected port, found '%1'" "$port"` (see |test-numeric|)
      `  if (( port < 1024 || port > 65535 )); then`
      `    raise -k "bad port" \\`
      `          -n "must be in range 1024..65535" \\`
      `          "port '%1' is out of range" "$port"`
      `  fi`
      `}`

  See also: |try|(script-try), |return|(builtin-return)

THRU                                             *builtin-thru* *thru*

  `thru [-c] [-t {dest}] [-a] [-L {bytes}]`

  Pass standard input to standard output unchanged. Equivalent to a fork-free
  `cat` with no arguments. Intended for two main use cases:

    - Capturing stdin into a variable without spawning an external process:
      `var=$(thru)` instead of `var=$(cat)`.
    - Acting as a no-op stage in a pipeline that can optionally tee, count,
      or limit the byte stream without disturbing the data flow.

  With no flags, `thru` is the identity function for byte streams: every
  byte read from stdin is written to stdout unchanged.

  Options ~

    `-t {dest}`, `--tee {dest}`
                  Write a copy of the stream to {dest} in addition to
                  stdout. {dest} can be a regular file path or any
                  filesystem path that the operating system maps to an
                  open file descriptor (`/dev/stderr`, `/dev/stdout`,
                  `/dev/fd/N`). By default the destination file is
                  truncated if it exists.

    `-a`, `--append`
                  Append to the tee destination instead of truncating it.
                  Only meaningful when `-t` is also given.

    `-c`, `--count`
                  After draining stdin, write the total number of bytes
                  that passed through to standard error. Does not affect
                  the pass-through output.

    `-L {bytes}`, `--limit {bytes}`
                  Pass through at most {bytes} bytes from stdin. Excess
                  input is discarded. The byte count snaps down to the
                  nearest UTF-8 character boundary so multi-byte characters
                  are never split.

  Behavior notes ~

    Errors writing to the tee destination are reported on stderr but do
    not interrupt the pass-through; the primary stream-to-stdout flow
    continues even if the side-channel write fails. Pipelines composed
    with `thru -t` therefore stay live even when the tee target becomes
    unavailable mid-stream (full disk, removed mount, etc.).

    When `-t` and `-c` are both given, the count reflects the bytes that
    were actually emitted (after `-L` truncation, if any). All side
    effects observe the same final byte count.

  Examples ~

      `var=$(thru)`
                                slurp stdin into `$var` without forking
                                an external `cat`

      `producer | thru -t /dev/stderr | consumer`
                                live-debug a pipeline: stream continues
                                to `consumer` while a copy is mirrored
                                to the terminal via stderr

      `producer | thru -t /tmp/snapshot.sqr | consumer`
                                capture a single run's data to a file for
                                later inspection

      `producer | thru -t log.txt -a | consumer`
                                append-mode tee, useful for accumulating
                                output across multiple runs

      `huge_producer | thru -L 4096 | inspect`
                                cap the stream at 4 KB, useful for
                                sampling unbounded producers

      `producer | thru -c | consumer`
                                report total bytes through this stage on
                                stderr at end of run

  See also: |builtin-quote|, |quoted-streams|

  Examples:

      `type echo`       echo is a shell builtin
      `type ls`         ls is /usr/bin/ls
      `type if`         if is a shell keyword
      `type ll`         ll is an alias for 'ls -la' ...

==============================================================================
ULIMIT                                           *builtin-ulimit* *ulimit*

  `ulimit [-n N] [-u N] [-s N] [-c N] [-v N]`

  Set soft resource limits for the current shell and processes it
  spawns. Each flag takes a numeric value. The hard limit is left
  unchanged; it is an error to set a soft limit above the hard limit.

  `-n {N}`   maximum number of open file descriptors
  `-u {N}`   maximum number of user processes
  `-s {N}`   maximum stack size in bytes
  `-c {N}`   maximum core dump file size in bytes (0 = disabled)
  `-v {N}`   maximum virtual memory (address space) in bytes

  Multiple flags may be combined in one call.

  Examples:

      `ulimit -n 4096`      raise file descriptor limit
      `ulimit -c 0`         disable core dumps

==============================================================================
UMASK                                            *builtin-umask* *umask*

  `umask [-S] [{mask}]`

  Get or set the file creation mask. The mask is subtracted from the
  permissions that programs request when creating new files.

  With no arguments, prints the current mask as a 4-digit octal number.

  `-S`   print the mask in symbolic form (`u=rwx,g=rx,o=rx`)

  {mask} forms ~

    Octal (e.g. `022`)   set the mask directly
    Symbolic             modify the mask using `chmod`-style notation:
                         `u`, `g`, `o`, `a` as who;
                         `r`, `w`, `x` as permissions;
                         `=`, `+`, `-` as operators.
                         Multiple clauses separated by `,`.

  Examples:

      `umask`              print current mask (e.g. 0022)
      `umask -S`           print symbolically (e.g. u=rwx,g=rx,o=rx)
      `umask 077`          no permissions for group or other
      `umask u=rwx,g=rx,o=rx`   set symbolically
      `umask a+r`          allow read for all (clear read mask bit)
      `umask g-w`          deny write for group (set write mask bit)

  `wait [{id} ...]`

  Wait for background jobs to finish. See |jobs-wait| for details.

WIDTH                                            *builtin-width* *width*

  `width [{string} ...]`
  `cmd | width`

  Print the display width of a string in terminal columns. This counts
  rendered cells, not bytes or code points: wide characters (CJK, many
  emoji) count as two columns and zero-width characters (combining
  marks) count as none.

  With arguments, the joined arguments are measured. With no arguments,
  the string is read from stdin. The result is printed as a single
  number followed by a newline.

  Useful for laying out aligned output by hand. |qtable|(function-qtable)
  uses it internally to size its columns.

  Examples:

      `width hello`              outputs:  `5`
      `width 日本語`             outputs:  `6`  (three wide characters)
      `printf 'café' | width`    outputs:  `4`  (combining mark is
                                                 zero-width)

  See also: |function-qtable|
